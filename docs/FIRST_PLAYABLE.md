# 第1～3章 First Playable

Status: Approved
Last updated: 2026-08-09

## 目的

ゲーム全体の全仕様を先に完成させるのではなく、プロローグから第3章終了までを実際のゲーム進行として通してプレイ可能にする。

第4章以降の全ストーリー、全妖怪、全村人イベント、全生活コンテンツの完成は目的としない。第3章までにプレイヤーが触れるシステムとコンテンツを実装可能な状態へ絞り込み、生活、戦闘、物語の基本ループが一つのゲームとして成立するか確認する。

## MVPとの区別

| 区分 | 目的 | 範囲 |
|---|---|---|
| MVP | 各主要システムの技術的・ゲーム的な成立を確認する小規模な垂直スライス | 既存の [`MVP.md`](MVP.md) を維持 |
| First Playable | 製品版と同じ入口から第3章終了までを通して遊べる状態を作る | 本文書で定義 |

MVPとFirst Playableを同一の完成条件として扱わない。

## 開始地点

- タイトル画面
- ニューゲーム
- ゲーム開始
- プロローグ
- 第1章開始

途中開始の技術デモにはせず、製品版と同じ入口から開始する。タイトル画面などのUI品質は最低限でもよい。

## 終了地点

第3章ボス「淀みの大樹」の撃破・浄化後、木霊が陽太の安全を確認して森へ去る場面までとする。

この時点では正式な仲間・友好関係にはならず、妖怪との本格的な交流は第4章以降へ接続する。

```text
プロローグ・第1章
  ↓
生活と初期戦闘を学ぶ
  ↓
第2章で生活・戦闘の基本ループを完成
  ↓
穢れ化・化け蛙を浄化
  ↓
第3章で木霊が陽太を守る姿を目撃
  ↓
妖怪への認識に疑問を持つ
  ↓
淀みの大樹を浄化
  ↓
木霊が森へ去る
  ↓
クラウドへ進行状態を保存
```

## 必須ゲーム基盤

- タイトル画面、ニューゲーム
- Googleアカウントによるログインとログアウト
- ユーザー別クラウドセーブとロード
- 主人公操作、マップ移動、エリア切り替え
- 会話、イベント、クエスト、ストーリー進行フラグ
- インベントリ、アイテム取得・消費、倉庫
- 時間、日付、就寝、翌日への移行
- NPC配置と基本スケジュール
- 商店

## アカウントとクラウドセーブ

First PlayableからGoogleアカウントによる認証を採用し、認証ユーザーごとに一意のユーザーIDを保持する。

- ゲームデータをユーザーIDへ紐付ける
- 別ユーザーは別のセーブデータを使用する
- PC、スマートフォンなど別端末でも同じアカウントのデータを利用できる
- 端末ローカルではなくクラウド側のユーザーセーブデータを正とする

主な保存対象：

- 現在の章、クエスト、イベントフラグ
- 日付、時刻、現在位置
- 所持金、インベントリ、倉庫
- 農作物、採取、NPC、村人の状態
- 戦闘進行、解放済み機能、ワールド状態

初期実装ではJSONなどによる単純なセーブ構造を許容する。ただし、将来データを分割できる構造を前提とする。

Google認証、ユーザーID、API、保存先の技術構成は次の技術設計ブロックで確定する。AWSを採用する場合は、Amazon Cognito、API Gateway、Lambda、DynamoDBを組み合わせたサーバーレス構成を第一候補とする。

ゲストプレイの採否は未決定とする。

## 生活システム

第3章までに次を実装する。

- 農業
- 採取
- 料理
- 釣り
- 調合
- 納品と村人依頼
- 神社への奉納
- 商店
- 倉庫

各生活システムには最低1回のチュートリアルを用意する。

| システム | 担当NPC |
|---|---|
| 農業 | しき |
| 料理 | 楓 |
| 釣り | 源三 |
| 調合 | 調合担当NPC。蓮と宗玄の整理後に確定 |
| 鍛冶 | 鉄斎 |

主人公宅では就寝、倉庫など必要な基本機能のみ実装する。大規模な家の増築、村の大規模復興は後回しとする。

## 戦闘システム

必須実装：

- 360度移動とタップ通常攻撃
- 攻撃方向補正、敵AI、攻撃予兆
- 移動回避、護身札、被弾、被弾後無敵
- 浄化、霊力、霊力回収、アイテムドロップ
- 結界、結界破損表現
- 結界で防御できる攻撃、結界貫通攻撃、結界必須攻撃
- 通常戦、ボス戦、戦闘終了処理

初戦闘では移動、回避、通常攻撃・清め、浄化、回収を扱う。その後、神主から結界を学ぶ。結界は高消費で多用できない切り札とし、回避主体の戦闘を維持する。

通常穢れは4～5種類程度を目安とし、近接、遠距離、突進、範囲、特殊など戦い方の差を優先する。第2章と第3章の章ボスを実装し、第3章までに基本的な攻撃種別判断を一通り経験できるようにする。

## 妖怪

第3章で物語へ直接関わる善良妖怪として木霊を実装する。

- 人間である陽太を穢れから守る
- 主人公がその姿を目撃する
- 主人公が木霊ではなく穢れを攻撃する
- 第3章ボス後に主人公と対面する
- 正式な仲間にはならず、森へ去る

座敷童子は第1～3章で背景、一瞬の姿、主人公の近くにいる気配など、伏線としてのみ登場させる。本格会話、友好度、妖怪札、正体説明は行わない。

第3章終了まで、次を解放しない。

- 妖怪友好度と妖怪Rank
- 妖怪へのプレゼント
- 妖怪札と妖怪札強化
- 妖怪支援、本格交流、共同生活
- 妖怪の里
- 共存度による本格的な世界変化

## 主要NPC

本実装を優先する。

- しき：序盤案内、村案内、農業チュートリアル
- 宗一郎：村とメインストーリー
- 神主：神社、結札、結界、穢れと妖怪の説明
- 楓：料理
- 源三：釣り
- 鉄斎：鍛冶
- 調合担当NPC
- 第3章の陽太と、その事件に必要な家族

村へ生活感を持たせるため、その他の村人も必要数配置する。ただし全友好度イベント、全個別ストーリー、全好物、全会話差分、全依頼は作らない。「村に存在すること」と「全コンテンツを完成させること」を分ける。

## マップ

第3章までに基本的に移動可能とする。

- 主人公宅、畑
- 村、村広場、神社
- 商店、なごみ亭、鍛冶屋
- 調合関連施設、釣り関連施設、村長関連施設
- 川、釣り場、森
- 必要な通常戦闘エリア
- 古池・第2章ボスエリア
- 淀みの大樹・第3章ボスエリア

山奥、洞窟、湖、廃寺、妖怪の里などは本格実装しなくてよい。入口や道を表示する場合は、崩落、工事、封鎖など世界内の理由で進入を制限する。

## コンテンツ量の目安

完成版の総数ではなく、First Playableの初期実装目安とする。プレイテストと章進行に応じて増減できる。

| コンテンツ | 目安 |
|---|---:|
| 作物 | 6種類前後 |
| 採取素材 | 8～10種類前後 |
| 魚 | 6種類前後 |
| 料理 | 8種類前後 |
| 調合品 | 4～5種類前後 |
| 通常穢れ | 4～5種類前後 |
| 村人依頼 | 8～12件程度 |
| サブイベント | 5～8件程度 |

種類数より、成長期間、用途、価値、攻略方法などの役割差を優先する。

## 完成条件

次を同一ユーザーのクラウドセーブを利用して、ゲーム開始から中断・再開しながら進行できること。

1. Googleアカウントでログインし、ユーザーのセーブデータを読み込む
2. ニューゲームからプロローグと第1章を進める
3. 生活、村、農業、神社、初戦闘、浄化、結界を体験する
4. 第2章の生活システム、依頼、奉納、化け蛙戦を完了する
5. 第3章で木霊が陽太を守る姿を目撃する
6. 淀みの大樹を浄化する
7. 木霊が森へ去り、第3章が終了する
8. 終了時の進行状態をクラウドへ保存し、再ログイン後も再開できる

## 技術基盤

First PlayableはTypeScript、React、Vite、Phaser、Tiledを使用し、スマートフォンブラウザを主要対象、PCブラウザを対応対象とする。スマートフォンは縦画面・9:16系を基準とし、PCは横長表示へ対応する。詳細は [`technical/TECH_STACK.md`](technical/TECH_STACK.md) と [`technical/DISPLAY_INPUT_FOUNDATION.md`](technical/DISPLAY_INPUT_FOUNDATION.md) を参照。

## 次の設計ブロック

次はPhaser Scene構成、GameBridge、JSONデータ構造を確定する。その後、Google認証とクラウド保存、セーブデータ、クライアント・サーバー責務、通信失敗、不正データ、競合の扱いを順次決定する。

以降は第4章以降の設計を先に広げず、第3章までの実装に必要な仕様を優先して決定する。
