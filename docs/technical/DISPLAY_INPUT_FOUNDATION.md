# 画面・スマートフォン／PC対応・入力基盤仕様

Status: Approved  
Last updated: 2026-08-09

## 目的と適用範囲

First Playableの画面、カメラ、HUD、入力およびReact / Phaserの表示責務を定義する。戦闘・料理・釣り・調合などの具体的な操作は各システム仕様書を正とし、本仕様では上書きしない。

## 対応画面

- スマートフォンを主要環境とし、縦画面・9:16系を基準に片手操作を考慮する。
- PCブラウザは16:9を含む横長画面へ正式対応し、縦長画面を中央へ固定表示しない。
- スマートフォンとPCで同一のゲームワールドと座標系を使用する。
- Canvas、カメラ、HUDを画面サイズに応じて調整し、キャラクターやマップを縦横へ引き伸ばさない。

## 視野とレスポンシブ表示

主人公周辺に「ゲームプレイ上の重要視野」を設け、次の情報をその範囲を基準に配置する。

- 敵、攻撃予兆、危険エリア、回避先
- 戦闘ギミックとボス攻略に必要な情報
- インタラクション対象

PCでは横方向、スマートフォンでは縦方向に余剰領域が見えることを許容する。ただし、余剰領域へ背景や装飾以外の重要情報を偏らせず、端末差が大きな攻略上の有利・不利を生まないようにする。

ウルトラワイド等ではカメラ表示範囲に上限を設け、それ以上の幅をUI余白または背景領域として扱う。

## Safe Area

ノッチ、Dynamic Island、パンチホール、ブラウザUI等を考慮し、重要HUDと操作領域はCSSのSafe Areaを反映した範囲内へ配置する。

## カメラ

- 通常時と戦闘時は主人公中央付近への自動追従を基本とし、自由カメラ操作は採用しない。
- マップ端ではマップ外が不自然に見えないよう追従範囲を制限する。
- ボス戦でも主人公追従を基本とし、重要視野と最大表示範囲を制御する。
- イベント中のみ追従解除、対象への移動、軽いズーム、主人公への復帰を許可する。
- 画面揺れは強い被弾、ボスの大技、結界破壊、大型物の破壊、重要イベントに限定する。

## HUD

全情報を常時表示せず、ゲーム状態に応じて切り替える。

| 状態 | 主な表示 |
|---|---|
| 通常フィールド | 日付、時刻、所持金、必要な生活情報 |
| 戦闘 | 護身札、霊力、結界、妖怪札、状態異常、ボスHP |
| 会話 | 会話UIを優先し、不要なHUDを抑制 |
| ミニゲーム | 料理・釣り・調合等の個別仕様に基づく専用UI |

スマートフォンとPCで情報量は原則共通とし、配置と操作領域だけを最適化する。スマートフォンでは移動を妨げず、移動しながら結界を押せることを優先する。PCでは横幅を活かして画面端へコンパクトに配置する。

## スマートフォン入力

- 移動：画面を押した位置を基準に、押下中に指をスライドした方向へ360度移動する。固定仮想スティックは使用しない。
- 通常攻撃：短いタップ1回で1回攻撃する。敵を正確にタップする必要はなく、既存のターゲット補正に従う。
- 結界：結界ボタンを押している間だけ展開し、展開中も移動できる。
- 妖怪札：既存仕様どおりタップで発動する。
- 非戦闘時：対象付近での長押しを会話、採取、調査、重要アイテム取得に使用する。
- 移動と結界の同時操作を可能にするため、複数Pointerによるマルチタッチへ対応する。

## PC入力

初期割り当ては次を基本とする。ゲームルールはスマートフォンと共通にする。

| 操作 | 入力 |
|---|---|
| 移動 | WASD / 矢印キー |
| 主要アクション・攻撃 | 左クリック |
| 結界 | Space |
| 妖怪札 | Q |
| メニュー | Esc |

将来キーコンフィグを追加できる構造とするが、First Playableで設定画面を必須とはしない。

## Input Context

入力競合を防ぐため、内部状態として次のInput Contextを管理する。

- `FIELD`
- `COMBAT`
- `DIALOGUE`
- `MENU`
- `MINIGAME`
- `CUTSCENE`

同じタップ、長押し、スライドでもContextに応じて意味を切り替える。`CUTSCENE`では通常移動と戦闘入力を無効化する。具体的な操作内容は各システム仕様書を正とする。

## React / Phaser責務

### Phaser

ゲームフィールド、マップ、キャラクター、生活、会話、戦闘、カメラ、ゲーム内HUD、エフェクトおよびミニゲームを担当する。

### React

タイトル、Google認証、アカウント、セーブデータ選択、設定、通信・システムエラー等のWebアプリ側画面を担当する。

両者はGameBridge相当のイベント層を介して連携し、内部オブジェクトを直接操作しない。イベント、payload、型、エラー処理は [`CLIENT_ARCHITECTURE.md`](CLIENT_ARCHITECTURE.md) を参照する。
