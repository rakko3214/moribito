# API起動診断・復旧QA

Status: Implemented  
Last updated: 2026-09-04

## 目的

Webアプリだけが起動してセーブAPIが停止している状態を、一般的な通信断と区別して確認できるようにする。API停止中も端末キャッシュを使ったプレイは継続でき、クラウド保存は未送信として保持する。

## 実装仕様

- `GET /health` は認証不要で `status`、`storage`、`apiVersion`、`schemaVersion` を返す。
- Webは起動直後、30秒ごと、ブラウザのオンライン復帰時に診断する。
- 診断は2.5秒でタイムアウトし、内部の通信エラー本文を画面へ露出しない。
- ヘッダーに確認中、応答時間、未接続を表示する。
- ポーズ画面にはAPIバージョン、保存Schemaバージョン、保存方式を表示する。
- 未接続から復旧した場合は再接続を通知し、既存の保留セーブ再送導線を利用する。
- Docker ComposeのWeb/API双方にhealthcheckを設定する。

## 手動確認

```powershell
docker compose up -d
docker compose ps
Invoke-RestMethod http://localhost:3001/health
```

1. API起動中にヘッダーが `API xxms` になること。
2. APIコンテナだけを停止すると、次回診断後に `API 未接続` になること。
3. API停止中も端末キャッシュから開始でき、保存状態が未保存になること。
4. APIを再開すると再接続通知が表示され、保存を再試行できること。
5. スマートフォン幅でもAPI表示が操作ボタンを押し出さないこと。

## 自動確認

- 正常レスポンスのバージョン・保存方式・応答時間
- 通信失敗と不正レスポンスの安全な未接続化
- APIヘルスペイロードがファイルパスを公開しないこと
- Compose設定が解決可能であること
